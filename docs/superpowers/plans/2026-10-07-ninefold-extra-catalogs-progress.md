# SoundCloud and YouTube connection

Scope approved by the user: remove Spotify URL import from the roadmap; add SoundCloud public sets/playlists and explicit YouTube video search. The user has no API keys yet, so both providers remain disabled by default. Existing Spotify/MusicBrainz search continues to work.

Implementation reuses the release model, API, cache, coalescing, circuit cooldown and board/share/PNG paths. SoundCloud caches an application token, rotates refresh tokens, invalidates unauthorized access tokens and bounds token-lock, token and search work by one deadline. YouTube keys are sent in a header; videos preserve title/channel attribution and do not interpret upload dates as release years. Broken entries are skipped while valid neighbors remain usable. No dependencies or URL-import flow were added.

The frontend uses a native Search source selector. SoundCloud searches with the existing debounce; YouTube runs only after Search YouTube or Enter. Source changes reset filters; edits cancel requests and clear stale results. Repeated Enter cannot restart a loading request or submit through held-key repeat.

Verification: 44 backend tests passed with Maven verify; 60 frontend tests, TypeScript checking and Vite production build passed. Regression checks include SoundCloud token reuse, 401 invalidation and refresh rotation, safe credential transport, cooldown/deadline handling, explicit-only YouTube requests and repeated Enter. A read-only reviewer found no critical or important issue; its minor keyboard finding was reproduced and fixed.

Local integration exercised real adapters through the Spring API and Vite proxy against disposable loopback HTTP catalog fixtures: both source searches returned normalized releases, default search excluded YouTube, both results were added to the same board. At 320 px the document client/scroll widths were both 305 px, and both new controls were 44 px high. Proof: target/catalog-integration-proof.jpg.
